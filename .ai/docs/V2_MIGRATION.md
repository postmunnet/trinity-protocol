# Trinity V2 Migration Notes

This document tracks behavior changes between Trinity v0.5 releases.
Existing sessions keep working; these notes describe how the CLI
generates *new* artifacts so that tooling and docs stay aligned.

---

## 2026-04-20 — Configurable session naming

### What changed

Session folder names are now generated by
`cli/core/session_naming.py` and driven by a new `session_naming:`
block in `.ai/ssot.yaml`.

**Before:**

```
sessions/2025-12-21_fix_login_bug/
         └────────────┬────────────┘
                date_str_slug
```

**After:**

```
sessions/0001_2026-04-20_22_21_pm_feat-v2-plan-implementation/
         └────────────┬────────────┘
             seq_date_hour_minute_ampm_type-slug
```

See [`docs/SESSION_NAMING.md`](SESSION_NAMING.md) for the full spec.

### Why

- Multiple sessions per day used to collide (identical `date_str` + slug).
- No way to filter by work type (feat / fix / docs / …).
- Users had to scan folder contents to know how many sessions existed.

### Impact

| Consumer                       | Impact                                                |
| :----------------------------- | :---------------------------------------------------- |
| `ai session new`               | Produces new canonical IDs out of the box             |
| Existing sessions              | Untouched — the CLI reads folder names as-is          |
| `ai snapshot` / `verify` / ... | No change — they operate on the path you pass         |
| `ssot.yaml`                    | Optional `session_naming:` block added (not required) |
| Docs / examples                | Refreshed to show the new ID in folder paths          |

### Action for downstream projects (e.g. a project consuming `.ai` as
a submodule)

1. `git submodule update --remote .ai` to pick up the new CLI.
2. Optional: add the `session_naming:` block to your SSOT if you want
   to override defaults (per-day seq, different type list, etc).
3. Old session folders stay on disk as-is; no rename required.

### Rollback

Remove the `session_naming:` block (or leave it absent) — the loader
falls back to the same defaults, so there is no behavioral drift. To
revert the CLI code itself, check out the previous commit of
`cli/commands/session.py` and `cli/core/session_naming.py`.
