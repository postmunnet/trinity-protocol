# Environment Variables Reference

**Purpose**: Centralized reference for all project environment variables
**Last Updated**: 2025-12-18
**Managed By**: `scripts/setup.sh` + `.ai/context_config.json`

---

## Quick Reference

```bash
# Source these variables in your shell:
source .env

# Or run setup wizard to configure:
./scripts/setup.sh
```

---

## Path Variables

### `APP_DIR`
- **Description**: Absolute path to project root directory
- **Default**: `<user-home>/Downloads/My_project/{{PROJECT_NAME}}`
- **Required**: ✅ Yes (must exist)
- **Usage**: Base path for all relative references
- **Override**:
  ```bash
  ./scripts/setup.sh  # Interactive prompt
  # OR
  export APP_DIR="/path/to/your/project"
  ```

---

### `DEPLOY_ROOT` / `DEPLOY_DIR`
- **Description**: Directory for code being prepared for deployment
- **Default**: `{{ACTIVE_DEPLOY_DIR}}`
- **Required**: ✅ Yes (created if missing)
- **Usage**: Active workspace for code edits before deployment
- **Override**:
  ```bash
  ./scripts/setup.sh  # Prompts for deploy directory
  # OR
  export DEPLOY_ROOT="/path/to/deploy"
  ```
- **Note**: This is the ONLY directory where code should be edited

---

### `PRODUCTION_DIR`
- **Description**: Production snapshot directory (read-only reference)
- **Default**: `${APP_DIR}/application_07_11_2025`
- **Required**: ⚠️ Optional (will NOT be auto-created)
- **Usage**: Reference for comparing current vs production code
- **Override**:
  ```bash
  ./scripts/setup.sh  # Enter production snapshot path
  # OR
  export PRODUCTION_DIR="/path/to/production/snapshot"
  ```
- **Safety**: Never edit files in this directory

---

### `LOGS_DIR`
- **Description**: Directory for application and deployment logs
- **Default**: `${APP_DIR}/logs`
- **Required**: ⚠️ Optional (created if missing)
- **Usage**: Store error logs, deployment logs, audit trails
- **Override**:
  ```bash
  ./scripts/setup.sh
  # OR
  export LOGS_DIR="/path/to/logs"
  ```

---

### `AI_DOCS_DIR`
- **Description**: Directory containing AI-readable documentation
- **Default**: `${APP_DIR}/ai-docs`
- **Required**: ✅ Yes (created if missing)
- **Usage**: Framework documentation location
- **Override**:
  ```bash
  ./scripts/setup.sh
  # OR
  export AI_DOCS_DIR="/path/to/ai-docs"
  ```

## Configuration Files

### `.ai/context_config.json`
**Purpose**: Machine-readable project configuration (schema + values)

**Structure**:
```json
{
  "properties": {
    "project_paths": {
      "properties": {
        "APP_DIR": { "default": "..." }
      }
    }
  },
  "values": {
    "project_paths": {
      "APP_DIR": "/actual/path"
    }
  }
}
```

**When to Edit**:
- Use `./scripts/setup.sh` (recommended)
- Or manually edit `.values` section (requires `jq`)

---

### `.env`
**Purpose**: Human-readable environment variables (shell-sourceable)

**Structure**:
```bash
APP_DIR="<user-home>/Downloads/My_project/{{PROJECT_NAME}}"
DEPLOY_ROOT="{{ACTIVE_DEPLOY_DIR}}"
# ...
```

**When to Edit**:
- Generated by `./scripts/setup.sh`
- Can be manually edited
- Auto-backed up before overwrite (`.env.bak.{timestamp}`)

## Usage Patterns

### In Documentation
Replace hardcoded paths with variable references:

```markdown
<!-- ❌ Hardcoded -->
Edit file at: {{ACTIVE_DEPLOY_DIR}}/...

<!-- ✅ Variable -->
Edit file at: ${DEPLOY_ROOT}/{{CONTROLLER_DIR}}/...
```

---

### In Scripts
Source variables before use:

```bash
#!/bin/bash
# Load environment variables
if [[ -f .env ]]; then
  source .env
else
  echo "Error: .env not found. Run: ./scripts/setup.sh"
  exit 1
fi

# Use variables
cd "${DEPLOY_ROOT}" || exit 1
```

---

### In AI Prompts
Reference variables when giving instructions:

```
"Edit the controller in ${DEPLOY_ROOT}/{{CONTROLLER_DIR}}/backend/note.php"
```

AI will expand variables from loaded context.

## Setup & Validation

### Initial Setup
```bash
# Run interactive wizard
./scripts/setup.sh

# Follow prompts for:
# - APP_DIR (project root)
# - DEPLOY_ROOT (working directory)
# - PRODUCTION_DIR (snapshot)
# - URLs (dev/staging/prod)

# Result: Creates .env and updates .ai/context_config.json
```

---

### Validation
```bash
# Check if variables are set
echo $APP_DIR
echo $DEPLOY_ROOT

# Verify directories exist
ls -ld $APP_DIR
ls -ld $DEPLOY_ROOT

# Source .env if needed
source .env
```

---

### Re-configuration
```bash
# Run setup again to change values
./scripts/setup.sh

# Backs up existing .env automatically
# Updates .ai/context_config.json values
```

---

## Troubleshooting

### Error: "Missing ${APP_DIR}"
**Cause**: Environment variables not loaded
**Fix**:
```bash
source .env
# OR
./scripts/setup.sh  # Re-run setup
```

---

### Error: "DEPLOY_ROOT does not exist"
**Cause**: Directory path incorrect or not created
**Fix**:
```bash
# Check current value
echo $DEPLOY_ROOT

# Re-run setup with correct path
./scripts/setup.sh

# Or create directory manually
mkdir -p "${DEPLOY_ROOT}"
```

---

### Error: ".env already exists"
**Cause**: setup.sh found existing .env
**Fix**:
```bash
# Backup is automatic (.env.bak.{timestamp})
# Choose: y = overwrite, N = keep existing
```

## Best Practices

### ✅ DO:
1. Run `./scripts/setup.sh` on first setup
2. Use variables in all documentation (never hardcode)
3. Source `.env` in scripts before using variables
4. Validate paths exist before operations
5. Update via `setup.sh` (maintains JSON sync)

### ❌ DON'T:
1. Hardcode paths in documentation
2. Edit `.ai/context_config.json` manually (use setup.sh)
3. Assume variables are set (always check/source)
4. Create PRODUCTION_DIR via setup (safety restriction)
5. Edit generated JSON values without regenerating

## Variable Naming Convention

**Pattern**: `{SCOPE}_{PURPOSE}` in SCREAMING_SNAKE_CASE

**Examples**:
- `APP_DIR` (application directory)
- `DEPLOY_ROOT` (deployment root)
- `DEV_URL` (development URL)

**Rationale**:
- Clear scope identification
- Environment variable standard
- Shell-compatible naming

## Migration from Hardcoded Paths

### Before (Hardcoded):
```markdown
Edit: {{ACTIVE_DEPLOY_DIR}}/{{APP_ROOT}}/...
```

### After (Variables):
```markdown
Edit: ${DEPLOY_ROOT}/{{APP_ROOT}}/...
```

### Find & Replace:
```bash
# Find hardcoded paths in docs
rg -l "{{ACTIVE_DEPLOY_DIR}}" ai-docs/

# Replace with variable
# (Use setup.sh to populate actual values)
```
